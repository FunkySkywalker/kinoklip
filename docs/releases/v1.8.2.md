## [Download Kinoklip 1.8.2 for Linux (AppImage)](https://github.com/SeniorMatt/kinoklip/releases/download/v1.8.2/Kinoklip-x86_64.AppImage)

Open it with [Gear Lever](https://flathub.org/apps/it.mijorus.gearlever) (or update it there), or make it executable (right-click > Properties > "Is executable") and double-click it. If double-clicking shows nothing, install `fuse3` or run it with `--appimage-extract-and-run`.

**New to Kinoklip? Read the [guide](https://github.com/SeniorMatt/kinoklip/blob/main/docs/guide/readme.md).** Questions and ideas: join us on [Discord](https://discord.gg/pCeHnvDn3x). Website: [seniormatt.github.io/kinoklip](https://seniormatt.github.io/kinoklip/).

**Update if you use 1.8.1:** a ripple trim could save a project that 1.8.1 then refused to open ("Damaged timeline: ... effect id is not unique"). 1.8.2 opens those projects with everything in them.

### Fixed
- Projects saved with duplicate effect ids open again; cutting, pasting and multicam clips give each effect its own id
- A project with a damaged timeline always opens now: overlapping clips move to a "Repaired" track, broken values are reset, and a message lists what was repaired
- The Project Manager reads damaged projects again instead of showing an old result
- Change Clip Duration on a clip with linked audio moves the other tracks once, not twice
- Ripple Delete and Ripple Cut keep every sync-locked track in sync: a clip running across the deleted part loses the same frames instead of the track staying behind, also when you delete audio clips
- Ripple trims on a clip's start (Trim tool, Ripple Start to Playhead) keep titles and music over the same picture; before, the other tracks lost frames at the clip's end
- A ripple trim whose first selected clip is on a locked track still trims its linked clips and keeps sync
- Ripple Overwrite with shorter material keeps the other tracks in sync
